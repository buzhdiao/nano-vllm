# 05 - 张量并行：TP 切分与通信

张量并行（Tensor Parallelism，TP）把单层的大矩阵乘切开到多卡。nano-vLLM 用 `tensor_parallel_size=N` 时会 spawn N-1 个子进程，各自持有一份模型的 1/N。全部实现集中在三个文件：`layers/linear.py`、`layers/embed_head.py` 和 `engine/model_runner.py` 的进程间通信部分。

## Megatron 式切分：列并行 + 行并行

**列并行**（ColumnParallelLinear，linear.py:66-93）：把权重按**输出维**切成 N 份，每 rank 计算 `X @ W_i^T`。输入 X 各 rank 完整相同，输出各持一块切片——**前向零通信**。本仓库里 qkv_proj、gate_up_proj 都用它：QKV 三段在输出维上并排，各 rank 拿到自己的 `num_heads` 个 Q 头和 `num_kv_heads` 个 KV 头（qwen3.py:50-56）。

**行并行**（RowParallelLinear，linear.py:167-201）：把权重按**输入维**切，每 rank 算出**部分和**，`dist.all_reduce` 求和后所有 rank 得到完整输出（linear.py:193-201）。bias 只在 rank 0 加一次，否则 all_reduce 会被加 N 遍（linear.py:196）。

两者串联（列并行 → 非线性 → 行并行）正好一次通信完成一个子层：attention 的 `qkv_proj`(列) → `attn` → `o_proj`(行)；MLP 的 `gate_up_proj`(列) → SiluAndMul → `down_proj`(行)。非线性作用在切片上不跨卡，所以层内只需一次 all_reduce。

## embedding 与 LM head

**VocabParallelEmbedding**（embed_head.py:9-55）沿**词表维**切：每个 rank 只持有 `[vocab/N, hidden]` 一段词向量。查表时先用布尔掩码判断每个 token id 是否落在本 rank 区间（embed_head.py:43），落段外则查到任意行后用 `mask.unsqueeze(1) * y` 清零，最后 `all_reduce` 求和——每个 token 只有一个 rank 查到非零向量，求和即完整 embedding（embed_head.py:51-53）。

**ParallelLMHead**（embed_head.py:57-87）输出 logits 时不用 all_reduce 而用 **gather**：各 rank 持有不同词表段的 logits，`dist.gather` 聚到 rank 0 后沿词表维 `torch.cat` 成完整 logits（embed_head.py:84-86）——只有 rank 0 需要完整 logits（采样只在主进程），通信量也只在 rank 0 落地。prefill 批是扁平拼接的多序列，先用 `cu_seqlens_q[1:]-1` 挑出每条序列最后一个 token 再投影（embed_head.py:76-78）。

## 权重加载：weight_loader 钩子

每个并行层的参数对象上都挂着 `weight_loader` 函数属性（linear.py:32）。`utils/loader.py` 加载 HF 权重时，发现参数带 `weight_loader` 就调用它完成切分拷贝：`narrow`/`chunk` 取出本 rank 分片再 `copy_`（如 linear.py:80-88）。`QKVParallelLinear` 还要处理 Q/K/V 三段宽度不同、GQA 下 KV 头更窄的偏移计算（linear.py:145-165）。

## 进程间协调：为什么不用 NCCL 传指令

rank 0 需要让子进程执行**同样的 Python 方法**（如 `run`），而 NCCL 只传张量不传调用。nano-vLLM 的做法极简：

- rank 0 把 `(方法名, 参数)` pickle 后写进 1MB 的 `multiprocessing.shared_memory`（model_runner.py:103-113），前 4 字节是长度头；
- 然后 `event.set()` 广播唤醒所有子进程（model_runner.py:112-113）；
- 子进程 `event.wait()` 阻塞等信、读信、`event.clear()`（model_runner.py:91-101）。

张量数据本身走 NCCL（all_reduce/gather），控制流走共享内存——各司其职。`Sequence` 还自定义了 `__getstate__/__setstate__`（sequence.py:103-119），decode 时只传 `last_token` 一个 id 而非整个 token 列表，大幅削减 pickle 体积。

## 小结

每层的通信次数固定为 1（all_reduce 或 gather），切分规则与 vLLM 的 Megatron 实现同构，但去掉了 custom all-reduce、流水并行、量化等分支，适合读源码理解 TP 本质。
